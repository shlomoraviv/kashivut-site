# קשיבות — בית הספר למיינדפולנס לנשים 🌸

אתר תדמית ומכירה לקורסי Mindfulness לנשים מהציבור הדתי והחרדי.
אתר סטטי (HTML + CSS + JS בלבד) — ללא תלות בשרת או בבסיס נתונים.

## מבנה האתר

| עמוד | קובץ |
|---|---|
| דף הבית | `index.html` |
| קורס MBSR | `mbsr.html` |
| קורס העמקה | `deepening.html` |
| ימי ריטריט | `retreat.html` |
| צוותי חינוך | `education.html` |
| אודות (יעל ברייר) | `about.html` |
| שאלות נפוצות | `faq.html` |
| צור קשר והרשמה | `contact.html` |
| עמוד 404 | `404.html` |

עיצוב: `assets/css/style.css` · סקריפטים: `assets/js/site.js` · תמונות: `assets/img/`

## הפעלה מקומית

פשוט פתחי את `index.html` בדפדפן, או:

```bash
python -m http.server 8791
# http://localhost:8791
```

## 🔐 מצב ניהול — עריכת טקסטים ישירות על המסך

באתר מובנה כלי עריכה: כל טקסט באתר יכול להיערך על המסך עצמו, בלי לגעת בקוד.

### איך נכנסים

1. בתחתית כל עמוד יש **כפתור "ניהול" שקוף לחלוטין** בפינה (מימין למטה).
   - במחשב: מעבירים את העכבר לפינה — הכפתור נחשף.
   - בנייד: נוגעים בפינה התחתונה.
   - בדרך נוחה במיוחד: פותחים את הכתובת עם `#ניהול` בסוף, למשל
     `https://shlomoraviv.github.io/kashivut-site/index.html#ניהול`
2. מוזן מסך סיסמה. הסיסמה נמסרת בנפרד ואינה כתובה בקוד — בקוד שמורה רק
   טביעת אצבע מוצפנת (SHA-256 עם מלח).
3. אחרי כניסה נכונה **כל טקסט באתר** (כותרות, פסקאות, כפתורים, קישורים,
   תפריט, פוטר, תוויות טפסים) הופך לאזור עריכה — לוחצים על הטקסט וכותבים.

### הסרגל בתחתית המסך

| כפתור | מה עושה |
|---|---|
| **שמור** | שומר את הטקסטים בדפדפן הזה. הטקסטים יוצגו מיד, ויישמר גיבוי. |
| **פרסם לאתר** | שומר **ומעדכן את האתר החי** — הטקסטים יופיעו לכל המבקרות תוך דקה. |
| **בטל שינויים** | מחזיר את הטקסט למצב שהיה לפני העריכה הנוכחית (בלי לשמור). |
| **שחזר למקור** | מחזיר את העמוד לנוסח המקורי של האתר. |
| **גיבוי** | רשימת הגיבויים, הורדת קובץ גיבוי מלא, ייבוא ויצירת קובץ גיבוי. |
| **הגדרות** | חיבור לפרסום אוטומטי (טוקן GitHub) וטיפול בטוקן. |
| **יציאה** | סגירת מצב הניהול (קיצור: `Esc`). |

עריכה גם: `Ctrl`/`⌘` + `S` = שמירה · `Esc` = יציאה · הדבקה מוכנסת כטקסט נקי,
כדי שעיצוב שהועתק ממקום אחר לא ישבור את העיצוב של האתר.

### איך זה נשמר (ולמה אי אפשר לפרוץ את זה בקלות)

- **הגנה:** הסיסמה עצמה לא נמצאת בקוד — נשמר רק גיבוב SHA-256 של מלח + סיסמה,
  וההשוואה נעשית בין גיבובים. אחרי 5 ניסיונות שגויים יש נעילה הולכת ומתארכת
  (דקה, 5 דקות, 15 דקות), ההתחברות פגה אחרי 45 דקות חוסר פעילות, ואף רכיב של
  מסך הניהול לא נמצא בדף עד שמזינים סיסמה נכונה. הטקסט שנשמר מנוקה אוטומטית
  מסקריפטים וממאפיינים מזיקים — גם בשמירה וגם בהצגה.
- **הערה כנה:** כל הגנה שהיא בצד הלקוח ניתנת בסופו של דבר לעקיפה בידי מי שיש לו
  גישה לקוד הדף ולדבאגר. הסיסמה מונעת כניסה סקרנית או מקרית, לא תקיפה נחושה.
  שינוי תוכן באתר החי דורש בכל מקרה גם הרשאת כתיבה לריפו.
- **מה שפורסם** נשמר בקובץ `assets/content.json` (האתר קורא אותו בכל טעינה
  ומציג את הטקסטים שבתוכו במקום אלה שבקוד).
- **טיוטה מקומית** נשמרת בדפדפן (`localStorage`) כדי שאפשר יהיה להמשיך לערוך
  בלי לפרסם, והיא מונחת מעל מה שפורסם.
- **גיבוי טקסט המקור** נשמר פעם אחת ואינו נדרס: `assets/content.original.json`
  בריפו + עותק בדפדפן. **כל שמירה** מוסיפה תמונת מצב ל-`assets/backups/` ול-
  גיבויים המקומיים, ואפשר להוריד קובץ גיבוי מלא בכל רגע.

### פרסום אוטומטי (חד-פעמי)

כדי שכפתור "פרסם לאתר" יעדכן את האתר החי, מזינים פעם אחת בהגדרות טוקן GitHub
(“fine-grained token”) עם הרשאה `Contents: Read and write` לריפו הזה.
הטוקן נשמר **רק בדפדפן של בעלת האתר** (לא בקוד, לא בריפו) ואפשר למחוק אותו
בכל רגע מהמסך הזה. בלעדיו אפשר עדיין להוריד את `content.json` ולעדכן ידנית.

חשוב: טוקן עם הרשאת **קריאה בלבד** (
`Contents: Read`) עובר את הקריאה אבל נכשל בפרסום. לכן כפתור "בדיקת חיבור" בודק גם
הרשאת כתיבה — הוא שולח בכוונה בקשה חסרה לקובץ קיים, שהשרת דוחה בלי לשנות דבר,
ומדווח אם ההרשאה קיימת.

### החלפת הסיסמה

מחשבים גיבוב חדש ומעדכנים את השורה `PASS_DIGEST` ב-`assets/js/editor.js`:

```bash
node -e "console.log(require('crypto').createHash('sha256').update('kashivut::nihul::v1::' + 'הסיסמה החדשה').digest('hex'))"
```

### אחרי שינוי בקוד

כשמשנים את `assets/css/editor.css` או את `assets/js/editor.js` — מעלים את מספר
הגרסה לפייל (`?v=c3` בקבצי ה-HTML) כדי שהדפדפנים יטענו את הגרסה החדשה.
